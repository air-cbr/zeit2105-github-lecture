# Collaboration guide

## Documentation

Use GitHub as a versioned archive of meaningful documentation milestones. Create documents and diagrams in the software your group prefers, keep one stable meaningful filename, and commit later substantial revisions. Branches and pull requests are optional when a significant documentation change benefits from review.

## Code

Use the full workflow: pull, branch, edit, inspect, stage, commit, push, pull request, review, merge, then pull updated `main`. Every student uses their own account and Git identity.

## Commit quality

Describe the milestone or behaviour, for example `Add initial Task 1 database design diagram` or `Implement owned-set entry and tests`.
